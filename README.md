# 设备测试画布

Windows 设备自动化测试工作台。用节点和连线编辑 Case，可模拟流程，或通过独立执行器控制继电器、设备、I²C、抓图和固件操作。画布支持拖动、缩放、复制粘贴和自动整理；运行时显示节点状态、图片和历史执行记录。

## 换一台电脑继续开发

1. 安装 64 位 Windows、Python 3.12（含 tkinter）、Git 以及设备和串口驱动。克隆此仓库后进入目录。
2. 在 PowerShell 中执行：

   ```powershell
   py -3.12 -m venv .venv
   .\.venv\Scripts\python.exe -m pip install -r requirements.txt
   .\.venv\Scripts\python.exe app.py
   ```

3. 在软件中新建项目和 Case。`examples/设备检查.case.json` 是原设备检查流程的脱敏路径副本，可复制到项目目录后打开；其中断言参数是原有配置，请按实际设备检查。
4. 实机运行还需要厂商 SDK：从已有安装或原电脑合法取得完整的 DLL 及其依赖、`platforms` 文件夹，放到仓库根目录的 `sdk` 文件夹，或者运行前设置 `$env:CANVAS_SDK_DIR = 'SDK绝对路径'`。SDK 和驱动没有放在此仓库；发行前需核实厂商授权。当前默认 COM7 / Channel 0，换机请核实串口和设备，关闭占用设备的其他程序。

配置 `assets/device.ini` 和固件 `assets/firmware.bin` 是本项目提供的设备文件。文件名的帧率标记可能不一致，按用户的实际设备配置核实。Case、测试记录、截图和设备 SDK 不随 Git 同步；需要时请另行安全备份 `项目` 目录。不要把包含敏感信息的运行数据提交到公开仓库。

## 测试

```powershell
.\.venv\Scripts\python.exe -m unittest -v test_canvas test_auto_wait test_continue test_gui_outcome
```

测试需要可交互的 Windows 桌面和 Tk；未提供原电脑私有 Case/历史记录时，依赖这些文件的测试会跳过。模拟运行不控制设备，真实运行会操作硬件；测试中使用模拟硬件，不等同于跨机实机验证。

## 功能与限制

- 连线决定执行顺序，目前只支持单条完整线性流程，不支持分支、循环或并发。
- 节点运行时失败会记录并继续后续步骤，最终汇总；预校验或执行器初始化失败仍会中止。退出码 0 为按流程规则完成、2 为执行完成但存在失败、1 为中止或异常。
- 固件下载曾在指定设备和固件上实机验证；备份、I²C 写入尚未完整实机验证。下载进度达到 100% 且收到终态时，按测试需求将节点视为完成，即使 SDK 报告失败；日志保留 SDK 状态和错误码，不能据此认定写入或校验成功。固件修改仅生成副本，不计算校验值。
- 默认在普通节点后等待至少 0.07 秒、继电器关后 5 秒、开后 8 秒；手动等待可抵扣。不同设备和流程仍需验证时序。
- 项目自带配置可用于原设备；SDK、驱动、设备权限和设备选择必须在新电脑重新核实。当前独立运行程序尚未在没有 PixelIDE 的新电脑上验证。
