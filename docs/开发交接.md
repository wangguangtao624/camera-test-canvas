# 开发交接

## 源码结构

- `app.py`：Tk 界面、画布操作、运行记录、图片预览、子进程和事件展示。
- `case_model.py`：Case 数据、连线顺序、参数及执行前校验、路径变量展开。
- `hardware_runner.py`：在独立进程中调用厂商 DLL，执行硬件节点；使用标准输出的 `@@CANVAS_EVENT@@` JSON 事件通知界面。
- `run_history.py`：读取运行摘要、快照和事件，回放历史记录。
- `test_canvas.py`：界面、流程、历史、失败继续和模拟硬件的回归测试。
- `assets/`：当前设备的 INI 和固件。`examples/` 为路径已替换的流程示例。

Case JSON 保存节点、参数和有向连线。UI 从连线取得执行顺序，运行时将快照、日志、事件和图片写入 Case 同级的 `测试结果/<Case>/<运行时间>/`。每次执行保留独立快照和记录；历史查看不会覆盖当前 Case。路径变量包含 `${APPDIR}`、`${CASEDIR}` 和 `${RUNDIR}`。

## 已有实测与未完成部分

原电脑曾实测继电器、设备开关、抓图、FPS/DN 和 I²C 读取；读取数值可能随设备寄存器实时变化。固件烧录、备份、I²C 写入没有完整实机验证。SDK/驱动与硬件在新环境需要重新验证；自动测试通过不代表这些操作已经实机验证。原始图像和日志可能包含业务数据，不自动上传。

固件编辑不重算 CRC；当前线性执行器不支持分支、循环和并发；停止与超时机制、设备发现和错误恢复仍需完善。历史记录依赖 Case 对应目录，重命名或移动时应注意迁移结果。使用前请保留设备配置和固件备份。

## 打包方向

现有可执行版由 GUI 和硬件执行器两个 PyInstaller 程序组成。GUI 应放在程序根目录的 `商务版/`，执行器放在 `runner_v6/`，厂商 DLL 放在 `sdk/`，配置固件放在 `assets/`。可安装 `requirements-build.txt` 后分别用 PyInstaller 的 `--onedir` 打包 `app.py`（GUI 使用 `--windowed`）和 `hardware_runner.py`，再按以上目录组装；`runner_v6` 中执行器名称须为 `设备执行器.exe`。打包后的完整目录、驱动及 DLL 授权需在目标电脑验证。本仓库未携带已编译程序或 SDK，不保证复制 exe 后即可脱离所有驱动。

## 建议后续工作

1. 在干净 Windows 电脑记录 Python、依赖、SDK 和驱动版本并跑回归，验证打包及路径。
2. 为硬件接口建立明确的设备选择、可取消与超时机制；扩充安全的模拟测试。
3. 在明确设备和固件版本后补充固件/写入的受控实机验证和备份恢复流程。
4. 设计节点分支、重复执行和结果导出，再扩展 Case 组合能力。
